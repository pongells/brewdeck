How it works

Three layers, one contract between them

Brewdeck is a separate touchscreen. It is not wired to the machine: it reads it over Wi-Fi through Gaggiuino's documented REST and WebSocket API. The firmware is split so each part can be replaced on its own. Only the core talks to the machine, and it checks every command before sending it.

UIThe screens you see above. Any graphics library; Brewdeck's own uses LVGL 9. It reads plain state, asks the core for things and gets told what happened.
↕ brewdeck_core.h, the core API (version 1)
CoreWi-Fi, finding the machine, REST and WebSocket, shot start and end, settings. The only part that sends anything, and only a short list: pick a profile, stop weight, brew temperature, save them, flush, tare. Never pumps, valves, heater or steam.
↕ panel, touch, backlight, memory
BoardOne folder per screen model: the Sunton ESP32-S3 4.3″ (800 × 480), and an experimental Guition ESP32-P4 port.
↕ Wi-Fi
MachineGaggiuino's own firmware, untouched. On this page the machine is fake: it replays a recorded shot and steam session.
Make it yours

A new look, or a new screen

Because the layers are separate, you can replace the UI without touching the network code, or bring Brewdeck to another ESP32 panel without touching the UI.

Write your own UI

A UI implements four functions (bd_ui_init, tick, event, wake) and calls the rest of the core API.

  1. Copy firmware/src/ui_minimal, a 150-line example (MIT licensed).
  2. Try it against the fake machine: UI=myui sim/build-emu.sh
  3. Build the firmware: UI=myui ./build.sh ui

Bring it to another screen

A board folder provides the panel, touch, backlight and memory. The core and the UI stay the same; the P4 port was done this way.

  1. Start from firmware/src/board/s3 (RGB panel) or board/p4 (DSI panel).
  2. Add an environment in platformio.ini with its own custom_board.
  3. Touch is shared (GT911); other controllers go in board/common.

Brewdeck is an unofficial Wi-Fi touchscreen for Gaggiuino machines. It is not made by or affiliated with the Gaggiuino project.

This page runs the same interface code as the screen, compiled to WebAssembly. The machine is fake: it replays a recorded shot and a recorded steam session, and answers profile, weight and temperature changes. Nothing leaves your browser.
