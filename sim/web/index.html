A second screen for your Gaggiuino machine

Brewdeck is an unofficial touchscreen that sits next to the machine and talks to it over Wi-Fi. It draws every shot live, compares it with the profile or your last shot, and handles profile, brew temperature, stop weight and flushing. Nothing on the machine is rewired or reflashed.

Build one

Brewdeck runs on its own small touchscreen next to the machine, connected only by Wi-Fi. No soldering, no wiring, nothing changed on the machine: you flash the screen over USB and pick your network on it.

What you need

  • A 4.3″ Sunton ESP32-8048S043-style screen (ESP32-S3, 800 × 480, touch, USB-C). The Guition JC4880P443 (ESP32-P4) works too, experimentally.
  • A Gaggiuino machine with its Wi-Fi web UI, on the same 2.4 GHz network as the screen.
  • A Mac or Linux computer with a USB cable and esptool.
Use a spare screen. Never flash the screen fitted to your machine: on a Gaggiuino Gen 3 machine it also runs the machine's Wi-Fi and web UI, which Brewdeck needs.

How it goes

  1. Download the package for your screen from the releases.
  2. Back up the screen's flash: the only way back to its original firmware.
  3. Flash it with the script in the package. It checks the chip and the backup first.
  4. Choose your Wi-Fi on the screen. It finds the machine by itself.

How it works

Brewdeck is a separate touchscreen. It is not wired to the machine: it reads it over Wi-Fi through Gaggiuino's documented REST and WebSocket API. The firmware has three layers, each replaceable on its own.

  1. UIThe screens above. Any graphics library; Brewdeck's own uses LVGL 9. It reads plain state, asks the core for things and is told what happened.
  2. through brewdeck_core.h, the core API
  3. CoreWi-Fi, finding the machine, live data, shots, settings. The only part that sends anything, and only a short list: pick a profile, stop weight, brew temperature, save them, flush, tare. Never pumps, valves, heater or steam.
  4. through the panel, touch, backlight and memory
  5. BoardOne folder per screen model: the Sunton ESP32-S3 4.3″ (800 × 480), and an experimental Guition ESP32-P4.
  6. over Wi-Fi
  7. MachineGaggiuino's own firmware, untouched. Here it is fake: it replays a recorded shot and steam session, and answers profile, weight and temperature changes.

Make it yours

Because the layers are separate, a new look does not touch the network code, and a new screen does not touch the interface.

Write your own interface

A UI names itself in BD_UI, implements four functions (bd_ui_init, tick, event, wake) and calls the rest of the core API.

  1. Copy firmware/src/ui_minimal, a 150-line example under the MIT license.
  2. Try it against the fake machine: UI=myui sim/build-emu.sh && sim/emu-myui
  3. Build the firmware, in firmware/: UI=myui ./build.sh ui

Bring it to another screen

A board folder provides the panel, touch, backlight and memory; the core and the UI stay the same. The P4 port was done this way. There is no step-by-step guide yet: start from firmware/src/board/s3 or board/p4, or open a discussion on GitHub.
